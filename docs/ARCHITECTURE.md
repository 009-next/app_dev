# 設計の要点

## 役割の分担

| 役割 | 担当 |
|---|---|
| 元に戻せる判断（カードの種類・情報不足・共有範囲を狭める提案・要約・次の業務の提案・資料の下書き） | AI |
| 元に戻せない操作と、安全の境界（リンク発行・共有範囲の拡大・ぼかしの削減・削除・送信） | コード（AI にはツールとして渡さない） |
| 確定（確認・同意・承認・共有・送信） | 人 |

判断のたびに、選択・理由・裏付け・使ったモデル・原価を、判断ログに残します。失敗したときは、AI に直させず、既定の動作に落とします。

## 処理の流れ

1. **タグ**（QR・NFC）→ 物のページ（担当・資料・カードの一覧・経緯の要約）
2. **カード作成**：写真は端末で隠してから送る（`app/static/mask.js`）。種類・説明文・共有範囲・要約を AI が提案
3. **会話から次の業務**（`app/talk.py`）：文字 → 作り手が確認 → 「私はこう理解しました」＋会話の引用 → 合っている／一部違う／違う → 承認 → 下書き
4. **通話画面の分析**（`app/vision.py`）：全面を隠し、開けた所だけの画像を AI へ。面積は端末が測り、サーバーが画素で二重に確かめる
5. **統合分析**（`app/fusion.py`）：音声を文字にして確認 → 文字と画面を突き合わせ → 対象物の赤丸・表（xlsx）・文書（docx）・メール下書き・次の選択肢。共有はオーナーが決めたフォルダへのコピー、送信は Gmail の作成画面のリンク（本人が自分の Gmail アドレスを設定すると、宛先・アカウントに入る。未設定なら宛先なし）

## モデルの使い分け

- 主：Orca Router 経由、予備：Claude 直。判断は安い順に試し、必要なときだけ上のモデルへ上げる。
- 画像を見るのは Claude の最上位のみ。音声分析は、音声対応モデル（Gemini 系）へ、別の設定・確認のうえで渡す。
- 原価は、応答で解決されたモデル名で計算する。

## 門（コードが強制）

- 画像分析・会話・音声分析・統合分析は、既定オフ（組織のオーナーの設定）。統合分析は 3 つの設定とセッションごとの確認が揃ったときだけ。
- 通話画面の分析：作り手の確認・機微な業種でない・カードの文章に機微な語がない・開けた面積が上限以内・回数の上限。
- AI の出力：引用の実在、個人情報の語・人名・長い数字列、会話や画像の中の指示への追従を検査。通らなければ採用しない。
- 共有先は、オーナーが決めた 1 か所のフォルダだけ。ファイル名はコードが作り、既存のファイル・リンクには書かない。
- 音声は保存しない。会話の文字は 7 日、統合分析の結果は 14 日で削除する。
- 共有リンクは推測できない値で、期限と取り消しを持つ。匿名でタグを読んだ人には、物の名前と問い合わせ窓口だけを見せる。

## テスト

`python -m pytest app/tests -q`（853 件）。AI の呼び出しは、偽のクライアントで差し替える。門を 1 つずつ外して、テストが失敗することを確認する変異テストも行っている。

## 環境変数

| 名前 | 用途 |
|---|---|
| `ORCA_API_KEY` / `ANTHROPIC_API_KEY` | AI の呼び出し（任意。なければ既定の動作） |
| `MIRUCON_ENV=dev` | 開発モード（ワンタイムコードをログに出す） |
| `MIRUCON_VISION=0` / `MIRUCON_TALK=0` / `MIRUCON_TALK_AUDIO=0` / `MIRUCON_FUSION=0` | 各機能の緊急停止 |
| `MIRUCON_DEMO_DIR` | デモ用音声（`demo_voice.wav`）のフォルダ |
| `MIRUCON_SPECS_PATH` | ツール定義（`specs.py`）の場所（既定は `app/specs.py`） |
