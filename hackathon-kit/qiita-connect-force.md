## Connect-Forceとは

Connect-Forceは、設備や現場作業を起点に、過去の記録、現在の注意点、次の対応案を一つの作業画面へ集めるAIエージェントです。

目標は、AIが勝手に業務を進めることではありません。根拠を集め、危険な条件では止まり、保存や追記は担当者が承認する。こうした手順をコードで固定し、記録を探す時間と転記の手戻りを減らします。

今回のMVPには2つの入口があります。

- PC版: 設備履歴、警告、対応シナリオを既定ではルール処理で表示するデモ画面。通常分析で外部LLMは呼びません。
- Eve会話: 自然言語の依頼から必要なToolを選ぶ入口。ORCA ROUTERまたはClaudeを、依頼の目的と安全条件に合わせて選択します。

## 何ができるか

機能名には、未来の選択肢を比べる「フォース・ビジョン」や、履歴をたどる「サイコメトリー」などの着想を使っています。ただし作品の要素を再現するものではなく、業務に必要な機能へ置き換えています。

| 着想 | Connect-Forceでの機能 |
| --- | --- |
| フォース・ビジョン | 根拠がそろう場合だけ、点検・修理評価・条件付き監視の3案を比較 |
| フォース・センス | 再故障、期限超過、記録の矛盾、危険語を「要確認」として検知 |
| サイコメトリー | 設備IDが完全一致する履歴を、ファイル名と行番号付きで表示 |
| 組分け帽子 | 依頼の目的、危険度、根拠量、予算に応じて処理を選択 |
| 必要の部屋 | 案件ごとに最小権限の作業室を作り、高リスク時は読取り専用へ切替 |
| 忍びの地図 | 根拠、警告、進行状態、承認待ちを同じ画面で確認 |
| フォース・プッシュ | 確認・引継ぎの下書きを作り、承認後だけ保存 |
| ポートキー | 同じPC・同じログインに限定した、短時間・一回限りの移動リンク |

## 実装で優先したこと

### 1. プロンプトではなくコードで止める

入力の形式、設備ID、許可するファイル、作業室の期限は決定的なコードで検査します。`masked://`形式以外の画像参照、Vault外のパス、Markdown以外の資料は受け付けません。

```ts
if (input.maskingApproved !== true) {
  throw new Error("マスキング確認がありません。");
}

if (!isAllowedObjectId(input.objectId)) {
  throw new Error("設備IDの形式が不正です。");
}
```

`masked://`参照は、確認済みのマスキング素材だけを扱うための入口です。デモでは合成データを使い、実パスや対象外ファイルを受け付けません。

### 2. 書き込みは内容確認と承認の後だけ

保存時は、分析に使った根拠と下書き内容のダイジェストを照合します。承認後に根拠が変わった場合、保存は止まります。`operationId`も検査し、同じ操作を再送しても成果物を増やしません。

### 3. コストの出し方を分ける

PC版の既定分析はルール処理なので、外部LLM呼出しは0回、モデルAPI費は0ドルです。音声分析はORCA ROUTERを使う任意機能として分離し、回数・同時実行数・出力トークン数をサーバー側で制限します。

2026年9月21日の実環境E2Eでは、27.684秒の音声を3回連続で処理し、すべてHTTP 200で完了しました。各回は766入力token・60出力tokenで、公開単価に基づく合計見積は$0.0011394です。デモ用の上限は$2以内に固定しています。

### 4. 音声は「確認済みテキスト」を基本に、外部分析は例外経路にする

会話・質問は、通常は利用者が確認・匿名化した文字起こしとしてMissionに追加します。ブラウザの音声認識やAqua Voiceで得た文章をそのまま信用せず、利用者が内容を確認してから使うためです。

今回、利用者が明示承認した場合だけ、ORCA ROUTERへ短いマイク音声を送る任意機能も加えました。ただし、次の制限をUIとサーバーの両方で強制しています。

- 送信のたびに確認チェックを要求する
- 最大30秒、3.9MB以下、マイク入力だけに限定する
- 画面共有、スピーカー、他アプリや通話のシステム音声を取得しない
- WebM/Ogg/WAV/MP3の形式と先頭シグネチャを検査する
- 送信先は固定したORCA ROUTERだけにする
- 音声バイト列とAPIの生応答を、作業室、判断マップ、下書き、監査記録、ログへ保存しない
- 要約結果をMissionへ自動投入しない。利用者が確認・匿名化して文字起こし欄へ入力した場合だけ利用する

音声分析の利用量は、入力・出力token、音声時間、見積額を分けて記録します。通常分析をルール処理に保ち、必要なときだけ短い音声分析を選べる構成です。

## 検証結果

2026年9月21日に、音声分析を含む自動検証と構成検査を実行しました。

| 項目 | 結果 |
| --- | --- |
| 単体・HTTP統合テスト | 43/43成功 |
| TypeScript | エラー0件 |
| Eve構成検査 | 成功 |
| 本番ビルド | 成功 |
| ORCA ROUTER音声E2E | 3/3 HTTP 200、サーバー実測27.684秒、合計見積$0.0011394 |
| PC画面 | 認証、分析、根拠表示、承認保存、単回ポートキー、音声分析UIを確認 |

音声分析では、未承認、30秒超過、形式不正の入力を拒否します。サーバーは実デコードで音声時間を計測し、音声バイト列とAPIの生応答を作業室・判断マップ・下書き・監査記録・ログへ残しません。

## ハッカソンの評価軸への対応

| 評価軸 | 現状 |
| --- | --- |
| セキュリティ | 認証、CSRF、実パス検査、承認、重複防止を実装。音声は都度確認、30秒、マイクのみ、ORCAのみ、保存なし。 |
| コストパフォーマンス | PC版の既定分析のモデルAPI費は0ドル。音声E2Eは3回合計$0.0011394の見積で、回数・トークン・予約額を制限。 |
| 信頼性 | 根拠・日付・矛盾を確認し、安全側に停止。43件の自動テストとORCA実環境E2Eで境界を確認。 |
| 自律性 | 目的、危険度、根拠、予算で処理を選び、候補を下書きとして提示。承認後だけ保存。 |
| 独創性 | 物の過去、現在の注意点、未来の選択肢、承認後の行動を一画面へ集約。 |

## デモで見るポイント

Connect-Forceのデモでは、設備IDから作業室を開き、根拠と警告を確認し、対応案を比較してから下書きを承認します。任意の音声分析では、明示送信、30秒上限、サーバー実デコード、ORCA ROUTERとのE2Eを確認できます。

AIの出力をそのまま保存せず、根拠と承認を通して次の業務へつなぐ。これがConnect-Forceが提供する業務体験です。
